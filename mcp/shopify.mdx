# Shopify

> **In one line:** Connect Shopify so your UnleashX agent can look up and refund orders, ship them with tracking, keep products and stock accurate, manage customers and storefront content, and start a workflow the moment an order lands.

| | |
|---|---|
| **Category** | CRM & Marketing |
| **Authentication** | Custom app Client ID + Client Secret |
| **Setup time** | ~10 minutes |
| **Difficulty** | Medium |
| **Best for** | Stores that want an agent handling order support, fulfillment and catalog upkeep end to end |

<Warning>
**This connector was rebuilt.** It now runs on the Shopify **Admin GraphQL API** and authenticates with a custom app's **Client ID and Client Secret**, not a pasted Admin API access token. If you connected Shopify before this change, the old connection will stop working — follow Section 3 and reconnect. The Storefront API token is no longer used at all.
</Warning>

## 1. Overview

Shopify is a commerce platform: products and variants, inventory across locations, orders and their fulfillments, customers, and the storefront's pages and blogs.

Once connected to UnleashX, your agent works against the Shopify Admin API on the store's behalf. It can search and read orders, refund them in full or in part, email an invoice, and ship a fulfillment order with tracking. It can create, update and delete products, add and reprice variants, and adjust or set stock at a specific location. It can manage customers, collections, storefront pages, blog articles and metafields, and build a draft order and turn it into a real one.

Eight polling triggers let a workflow start on its own — a new order, a paid order, a cancelled order, a refund, a new customer, a new product, a new draft order, or a new page.

Connecting Shopify to UnleashX turns store operations into conversation and automation: "where's my order" gets answered and, if needed, refunded; a new order fires a workflow; stock corrections land at the right location without anyone opening the admin.

## 2. What you'll need

- A Shopify store and its **shop domain** (`your-store.myshopify.com`).
- A **Shopify Partner account** to create the custom app — [partners.shopify.com](https://partners.shopify.com/), free to sign up.
- Permission to install an app on the store (store **owner**, or staff with app-install rights).
- The app's **Client ID** and **Client Secret** once it's installed.

<Note>
Shopify no longer issues the old non-expiring `shpat_` Admin API access tokens for newly created admin custom apps. UnleashX stores the Client ID and Client Secret and exchanges them for a short-lived Admin API token automatically, refreshing it about every 24 hours — which is why you supply two values instead of a token.
</Note>

## 3. Get your credentials

<Steps>
<Step title="Create the app in the Partner Dashboard">
Go to [partners.shopify.com](https://partners.shopify.com/) → **Apps → Create app**. Name it "UnleashX".
</Step>
<Step title="Set it to custom distribution">
In the app's **Distribution** settings choose **Custom distribution** and enter the store's `your-store.myshopify.com` domain. This locks the app to that one store.

<Warning>
Distribution can't be changed once it's set. Pick **Custom distribution** — an app set up for the public app store won't work here.
</Warning>
</Step>
<Step title="Request the Admin API scopes">
In **Configuration → Admin API integration**, enable the scopes for the tools you plan to use (table below).
</Step>
<Step title="Install the app on the store">
Generate the install link from the app's overview and install it on the store. Nothing authenticates until the app is installed.
</Step>
<Step title="Copy the Client ID and Client Secret">
Open the app's **Client credentials** (also shown as API key and API secret key) and copy both.

<Warning>
Treat the Client Secret like a password. Anyone holding both values can mint an Admin API token for your store.
</Warning>
</Step>
</Steps>

### Scopes this app needs

Grant only what your workflows use. When a call fails for a missing scope, the error names the scope it wanted.

| Scope | Needed for |
|---|---|
| `read_orders`, `write_orders` | Order search and reads, refunds, invoices, tags |
| `read_fulfillments`, `write_fulfillments` | Creating fulfillments and updating tracking |
| `read_merchant_managed_fulfillment_orders`, `write_merchant_managed_fulfillment_orders` | Listing and acting on fulfillment orders shipped from your own locations |
| `read_products`, `write_products` | Products, variants, collections |
| `read_inventory`, `write_inventory` | Stock levels, adjusting and setting quantities |
| `read_locations` | Listing inventory locations |
| `read_customers`, `write_customers` | Customer search, create and update |
| `read_content`, `write_content` | Storefront pages, blogs and articles |
| `read_draft_orders`, `write_draft_orders` | Draft orders and completing them |

<Info>
You'll provide three things when connecting: the **shop domain**, the **Client ID**, and the **Client Secret**.
</Info>

## 4. Connect on UnleashX

<Steps>
<Step title="Open your agent">
Sign in at [https://www.tryunleashx.com](https://www.tryunleashx.com) and open the agent you want to connect.
</Step>
<Step title="Open Data Connectors">
In the agent, go to **Data Connectors** and find **Shopify**.
</Step>
<Step title="Fill in the fields">
Click **Connect** / **Add** / **Configure** and enter:

| Field | What to enter |
|---|---|
| **Shop Domain** | `your-store.myshopify.com` — the `.myshopify.com` address, not your custom domain |
| **Client ID** | From the custom app's client credentials |
| **Client Secret** | The matching secret |
| **Account Name** | A label for this connection inside UnleashX |
</Step>
<Step title="Confirm">
Save. The status will switch to a **Connected** badge.
</Step>
</Steps>

<Note>
Each connection is one store. To run several stores, add one connection per store — every tool also accepts an optional `shop_domain` to target a specific connected store explicitly.
</Note>

### Use Shopify in a Workflow

Once connected, you can add **Shopify** to any automation from the **Workflows** builder. Its triggers and tools appear in the Apps panel, marked with an **MCP** badge.

<Steps>
<Step title="Add a trigger node">
Open **Workflows → New Workflow**. On the canvas, click **+ Add Trigger**. In the **Paths** panel, open the **Apps** tab and select **Shopify** — its **Triggers** are listed underneath. Use the search box if you have many connectors.
</Step>
<Step title="Add an action node">
Click the **+** below any node to add a step, then pick **Shopify** again — this time the panel lists its **Actions**.
</Step>
<Step title="Configure the step">
Fill in the fields for the trigger or action you picked. Required fields are marked with a red asterisk (*).
</Step>
<Step title="Add or select your account">
Under **Selected account**, choose an already-connected account, or click **Add Account** to connect one now.
</Step>
<Step title="Save and test">
Click **Save**. Use **Test** to verify the step, then toggle **Publish** when the workflow is ready.
</Step>
</Steps>

<Note>
The steps are the same for every connector. For the full workflow builder guide, see [Using MCP in Workflows](/mcp/workflows).
</Note>

## 5. Available tools

Names match the **Workflows** Apps panel, which lists them alphabetically; they're grouped here by what they act on. The **Tool ID** is what the agent calls behind the scenes. Every tool also takes an optional `shop_domain` when you have more than one store connected.

**Orders**

| Tool | Tool ID | What it does | Required | Changes data? |
|---|---|---|---|---|
| Search Orders | `shopify_search_orders` | Searches orders, newest first | — | No |
| Get Order | `shopify_get_order` | Gets one order with line items, customer, addresses and fulfillments | `order_id` | No |
| Refund Order | `shopify_refund_order` | Refunds an order in full or in part | `order_id` | ⚠️ Yes |
| Send Order Invoice | `shopify_send_order_invoice` | Emails the customer an invoice for an order | `order_id` | ✏️ Yes |

**Fulfillment**

| Tool | Tool ID | What it does | Required | Changes data? |
|---|---|---|---|---|
| List Fulfillment Orders | `shopify_list_fulfillment_orders` | Lists what can be shipped for an order, and from where | `order_id` | No |
| Create Fulfillment | `shopify_create_fulfillment` | Ships a fulfillment order, optionally with tracking | `fulfillment_order_id` | ✏️ Yes |
| Update Fulfillment Tracking | `shopify_update_fulfillment_tracking` | Updates tracking on an existing fulfillment | `fulfillment_id` | ✏️ Yes |

**Products and variants**

| Tool | Tool ID | What it does | Required | Changes data? |
|---|---|---|---|---|
| Search Products | `shopify_search_products` | Searches products, newest first | — | No |
| Get Product | `shopify_get_product` | Gets one product with variants and inventory item IDs | `product_id` | No |
| Create Product | `shopify_create_product` | Creates a product (`status` defaults to `DRAFT`) | `title` | ✏️ Yes |
| Update Product | `shopify_update_product` | Updates a product; omitted fields are left unchanged | `product_id` | ✏️ Yes |
| Delete Product | `shopify_delete_product` | Permanently deletes a product and its variants | `product_id` | ⚠️ Yes |
| Search Product Variants | `shopify_search_product_variants` | Searches variants across the store | — | No |
| Create Product Variants | `shopify_create_product_variants` | Adds variants to a product (bulk — Shopify has no single-variant create) | `product_id`, `variants` | ✏️ Yes |
| Update Product Variants | `shopify_update_product_variants` | Updates variant price, SKU, barcode, compare-at price | `product_id`, `variants` | ✏️ Yes |

**Inventory**

| Tool | Tool ID | What it does | Required | Changes data? |
|---|---|---|---|---|
| List Locations | `shopify_list_locations` | Lists inventory locations — needed before changing stock | — | No |
| Get Inventory Levels | `shopify_get_inventory_levels` | Stock for one item across locations: available, on hand, committed | `inventory_item_id` | No |
| Adjust Inventory | `shopify_adjust_inventory` | Changes stock by a relative amount at one location | `inventory_item_id`, `location_id`, `delta` | ⚠️ Yes |
| Set Inventory | `shopify_set_inventory` | Sets stock to an exact number at one location | `inventory_item_id`, `location_id`, `quantity` | ⚠️ Yes |

<Tip>
Use **Adjust Inventory** when something happened (three units damaged: `delta: -3`). Use **Set Inventory** when your own system is the source of truth and you're overwriting Shopify's number.
</Tip>

|---|---|---|---|---|

|---|---|---|---|---|
| List Collections | `shopify_list_collections` | Lists collections, most recently updated first | — | No |
| Create Collection | `shopify_create_collection` | Creates a collection — smart with `rules`, manual without | `title` | ✏️ Yes |
| Add Products To Collection | `shopify_add_products_to_collection` | Adds products to a manual collection | `collection_id`, `product_ids` | ✏️ Yes |

| Tool | Tool ID | What it does | Required | Changes data? |
|---|---|---|---|---|
| Add Tags | `shopify_add_tags` | Adds tags to an order, customer, product, draft order or article | `resource_id`, `tags` | ✏️ Yes |
| Remove Tags | `shopify_remove_tags` | Removes tags from the same resource types | `resource_id`, `tags` | ✏️ Yes |
| Get Metafields | `shopify_get_metafields` | Reads custom metafields on a resource | `resource_id` | No |
| Set Metafield | `shopify_set_metafield` | Creates or overwrites a metafield (upsert) | `resource_id`, `namespace`, `key`, `value` | ✏️ Yes |
| Get Shop | `shopify_get_shop` | Store name, primary domain, currency, timezone and plan | — | No |

**Triggers**

| Trigger | Trigger ID | Fires when |
|---|---|---|
| On New Order | `shopify_on_new_order` | An order is placed |
| On New Paid Order | `shopify_on_new_paid_order` | An order reaches paid status |
| On New Cancelled Order | `shopify_on_new_cancelled_order` | An order is cancelled |
| On New Refund | `shopify_on_new_refund` | An order is refunded |
| On New Customer | `shopify_on_new_customer` | A customer is created |
| On New Product | `shopify_on_new_product` | A product is created |
| On New Draft Order | `shopify_on_new_draft_order` | A draft order is created |
| On New Page | `shopify_on_new_page` | A storefront page is created |

<Note>
**Refunds and stock changes are idempotent.** A retried step that sends the identical payload is collapsed by Shopify rather than refunding twice or double-counting stock. When you genuinely mean to repeat an identical operation — refunding the same amount a second time on purpose — pass your own `idempotency_key` to force it through.
</Note>

## 6. Example usage

**"Where's order 1042, and refund the shipping — it arrived late."**
Runs **Get Order** → **Refund Order** with a shipping amount.

**"Ship order 1042 with DHL tracking 1234567890."**
Runs **List Fulfillment Orders** → **Create Fulfillment** with the tracking number and company.

**"We found three damaged units of SKU-22 at the Mumbai warehouse."**
Runs **Search Product Variants** → **List Locations** → **Adjust Inventory** with `delta: -3`.

**"When a paid order comes in over ₹10,000, tag it VIP and tell the team on Slack."**
A workflow starts on **On New Paid Order**, branches on the total, then runs **Add Tags** and your messaging connector.

**"Build a quote for this wholesale buyer and send them a payment link."**
Runs **Create Draft Order** and returns the invoice URL; **Complete Draft Order** converts it once they pay.

## 7. Permissions & data access

**UnleashX CAN:**
- Read and search orders, products, variants, customers, collections, pages, articles, inventory and metafields.
- Refund orders, send invoices, and create fulfillments with tracking.
- Create, update and delete products and pages; adjust and set stock; manage tags and metafields.
- Create draft orders and complete them into real orders.
- Start workflows on eight store events.

**UnleashX CANNOT:**
- Do anything the installed app's scopes don't allow — the failure names the missing scope.
- Take payments or complete checkout on a shopper's behalf.
- Change store settings, themes, staff accounts or billing.
- Reach any store other than the one the app is installed on.

**To disconnect:** In UnleashX go to **Data Connectors → Shopify → Disconnect**. To fully revoke access, uninstall the app from **Shopify admin → Settings → Apps and sales channels**. Revocation is immediate — the short-lived Admin token can no longer be minted.

## 8. Troubleshooting

| Problem | What it means | How to fix it |
|---|---|---|
| `401` / `403` on every call | The app isn't installed on the store, or the Client ID/Secret is wrong | Confirm the app is installed, then re-enter both values |
| `403` on one tool only | That tool's scope wasn't granted | Add the scope the error names, reinstall the app, reconnect |
| `429 Too Many Requests` | Shopify's GraphQL limit bills by query **cost**, not request count | Lower the `limit` on list tools rather than just retrying |
| An action "succeeds" but nothing changed | Shopify reports write failures at HTTP 200 in `userErrors` | The connector surfaces these as errors — read the message; it names the field |
| A refund ran twice | Two genuinely different operations hashed to the same idempotency key, or you retried expecting a second refund | Pass an explicit `idempotency_key` when a repeat is intentional |
| Domain rejected at connect time | The value isn't a `.myshopify.com` address | Use `your-store.myshopify.com`, not your custom domain |
| Old setup stopped working | This connector no longer accepts a pasted Admin API token | Create a custom app and reconnect with Client ID + Client Secret |

For general connector issues, see [/mcp/integrations](/mcp/integrations).

## 9. Frequently asked questions

**Is my store data stored by UnleashX?**
No. Tools call the Shopify Admin API live and return the result. UnleashX keeps only the bookkeeping a polling trigger needs to know what it has already seen.

**Why Client ID and Client Secret instead of an access token?**
Shopify's Admin API token for a custom app is now short-lived. UnleashX mints a fresh one from the two values roughly every 24 hours, so there's nothing for you to rotate manually.

**What happened to the cart and newsletter tools?**
They used the Storefront API and are gone. Order creation is now **Create Draft Order** → **Complete Draft Order**; customer sign-up is **Create Customer**.

**Can the agent take payments?**
No. It can produce a draft order with an invoice URL, and the buyer pays through Shopify's checkout.

**Can I connect more than one store?**
Yes. Add one connection per store, and use `shop_domain` on a step when you need to be explicit about which one it targets.

**Which API version is this?**
Admin GraphQL `2026-07`. The REST Admin API isn't used — it's been legacy since October 2024 and unavailable to new custom apps since April 2025.
